# Vibe Security Radar — Web Dashboard

Next.js static site that visualizes vulnerability data produced by [cve-analyzer](../cve-analyzer/).

## Stack

- **Next.js 16** (App Router, static export)
- **React 19** + **TailwindCSS 4**
- **Recharts** for charts (pie, bar)
- **Radix UI** primitives (dialog, tooltip, badge, etc.)

## Setup

```bash
npm install
```

## Data

The site reads one validated research ledger at build time:

| File | Contents | Generated by |
|------|----------|--------------|
| src/generated/research-data.json | Confirmed true-positive catalog | ../scripts/publish_tp_ledger.py |

src/lib/research-data.ts loads it and postbuild runs
npm run research:data:check (the research-data and research-status test
suites) as the acceptance gate. The generator fills severity/CWE/description/
references from the local advisory database plus pinned cvelistV5, and language
from local code hunk extensions or clone marker files — never the GitHub API.
Missing values stay null and are reported rather than guessed.

The legacy 36-case catalog (data/, generate_web_data.py) is archived under
archives/legacy-36-web-catalog/; the frozen data-refresh campaign (scripts,
tests, web release gates) is under archives/legacy-web-data-campaign/. Neither
feeds the site.

To regenerate the site data after changing the research inputs:

```bash
# From the repo root
python3 scripts/publish_tp_ledger.py
```

`npm run build` in `web/` runs the publisher and `scripts/site_preflight.py` first. Public JSON is English-only.

## Deploy

Production is Cloudflare Pages (`vibe-security-radar`), domain https://vibesecradar.com/.

```bash
cd web
npm run deploy
```

Pushes to `main` also deploy through `.github/workflows/deploy-pages.yml`.

## Development

```bash
npm run dev          # Dev server at http://localhost:3000
npm run build        # Production build (static pages)
npm run start        # Serve production build
npm run lint         # ESLint
npm run test         # Vitest
npm run test:watch   # Vitest watch mode
```

## Pages

| Route | Description |
|-------|-------------|
| `/` | Dashboard — stats cards, severity chart, monthly trend, recent vulnerabilities |
| `/cves` | Vulnerability table — filterable by severity, tool, search |
| `/cves/[id]` | Detail page — fix commits, bug-introducing commits, AI signals, LLM verdict |
| `/analytics` | Tool, severity, language, and monthly distributions |
| `/tools` | Compatibility redirect to `/analytics` |
| `/about` | How we verify AI-contributed vulnerabilities |
