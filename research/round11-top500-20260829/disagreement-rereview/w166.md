# w166 re-research

## Decision

**AGREE** with the disagreement memo. Recommended primary verdict: **NOT_AI**. Recommended review verdict: **CONFIRMED**, with a corrected non-causal `remaining_gap` for fixed-release/tag membership. The vulnerability, public atomic introducers and their immediate parents, affected-tag membership, branch-level repair chain, and BIC-only human attribution all replay. The absence of a post-fix 4.5/5.0 tag does not negate the causal verdict.

## Vulnerability mechanism

The vulnerable Company Admin templates form reads `company` and `search` using `optional_param(..., PARAM_CLEAN)`, then places both values directly into SQL: three `LIKE '%$search%'` expressions and `ccf.companyid=$company`, followed by unparameterized `get_records_sql()` / `get_records_select()` calls. The introducing blob shows the inputs at lines 24-30 and the sinks at lines 152-180 ([introducing source](https://github.com/iomad/iomad/blob/3f09d1b3d7f6e329bf4869af0372c33f6f298038/blocks/iomad_company_admin/iomad_templates_form.php#L24-L30), [vulnerable SQL](https://github.com/iomad/iomad/blob/3f09d1b3d7f6e329bf4869af0372c33f6f298038/blocks/iomad_company_admin/iomad_templates_form.php#L152-L180)). Access requires `block/iomad_company_admin:managetemplates`; the reporter states that a company administrator exploited the `IOMAD_405_STABLE` form to full multi-tenant database compromise ([reporter issue](https://github.com/iomad/iomad/issues/2559)). CVE-2026-1517 is `PUBLISHED`, assigns CWE-89/CWE-74, and describes a remotely executable SQL injection in the Company Admin Block ([CVE record](https://www.cve.org/CVERecord?id=CVE-2026-1517)).

Local object replay found no `blocks/iomad_company_admin/iomad_templates_form.php` in either immediate parent. Both commits add the file with blob `58ea69b01b193ed1d316df575fcf5fc68b38eb40` and have stable patch-id `4d7d11dfd35ea29956300d3dd2e9c8865a2a7abb`; therefore neither is a move or refactor. Keeping `3f09d1b3d7f6e329bf4869af0372c33f6f298038` as the primary `introducer_sha` is defensible for the exploited 4.5/5.0 lineage, provided the earlier parallel 3.1 object remains explicitly recorded.

## Squash or member decomposition

Each BIC is a single-parent, eight-file implementation of issue #364 and directly creates the 236-line vulnerable form. Issue #364 is an issue, not a pull request, and exposes no finer public member commit ([issue #364](https://github.com/iomad/iomad/issues/364)). A clone-wide, path-scoped `git log --all -S` replay returned only the two equivalent first-writes before the later repair copies. Thus the commits are feature aggregates, but no finer public member can be reconstructed; under the protocol, the applicable branch object is the smallest surviving public BIC rather than an unresolved squash.

## Direct fix or unpatched state

On 4.5, `0c9f8d9ee05d1513162eb0d6b108db85c1796e3a` replaces the direct interpolation with `sql_like()` placeholders and a `:companyid` placeholder, but still calls `get_records_sql($sql)` without its parameter array and uses the wrong `ccf` alias. The direct completing fix is `e7d51c4a13f2d43380b173df33ed37e0241bdd4e`, which changes the alias to `cct` and calls `get_records_sql($sql, $selectparams)` ([initial 4.5 repair](https://github.com/iomad/iomad/commit/0c9f8d9ee05d1513162eb0d6b108db85c1796e3a), [completing 4.5 fix](https://github.com/iomad/iomad/commit/e7d51c4a13f2d43380b173df33ed37e0241bdd4e)). ## Remaining gap

No post-fix 4.5 or 5.0 release tag is currently published in the repository, so the first fixed release artifacts cannot be named. The CNA record still labels versions 4.5 and 5.0 affected, while the GitHub advisory says upgrading to 4.5 LTS/5.0 addresses the issue and the vendor says the latest stable branch heads were fixed ([CVE record](https://www.cve.org/CVERecord?id=CVE-2026-1517), [GitHub advisory](https://github.com/advisories/GHSA-2xjx-542r-phch), [vendor statement](https://github.com/iomad/iomad/issues/2559#issuecomment-3841174677)). This is a release-labeling/publication gap, not a BIC, fix, or AI-attribution gap.
