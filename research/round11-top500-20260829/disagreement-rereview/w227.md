# w227 re-research

## Decision

**AGREE** with the disagreement memo. Recommended primary verdict: `NOT_AI`. Recommended review verdict: `CONFIRMED`. The independent review reproduced the vulnerability, BIC, parent, releases, and fix, but its demand for separate affirmative proof of “human-only authorship” is stricter than the stated gate. The BIC object itself names the repository owner account as both author and committer and contains no AI, bot, or generator marker ([BIC](https://github.com/mmaitre314/picklescan/commit/c1d5abdcc740e0d08a0d12d015d08e1e6f29a67e)).

## Vulnerability mechanism

The published CVE is real, not rejected or withdrawn: the CVE List V5 record has `state=PUBLISHED`, identifies CWE-184, and marks versions `<0.0.25` affected and `0.0.25` unaffected ([CVE-2025-71355 record](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2025/71xxx/CVE-2025-71355.json)). The vendor advisory explains the exact gadget: a pickle `GLOBAL` resolves `numpy.testing._private.utils.runstring`, whose `__reduce__` arguments execute Python code; a caller sees `infected_files == 0` and then calls `pickle.load()` ([vendor GHSA-fj43-3qmq-673f](https://github.com/mmaitre314/picklescan/security/advisories/GHSA-fj43-3qmq-673f)).

I replayed that flow from the exact `v0.0.24` source object `75e60f2c02f3f1a029362e6f334e1921392dcf60`, without checking out or modifying the clone. A protocol-4 pickle whose reduce callable was `numpy.testing._private.utils.runstring` was reported as `SafetyLevel.Suspicious` with `issues_count=0`, `infected_files=0`, and `scan_err=False`; unpickling the same bytes then set a process-local environment marker through the supplied Python string. This follows the source path in which an unlisted global becomes `Suspicious` but does not increment `issues_count`, and `infected_files` is derived solely from `issues_count` ([pinned v0.0.24 scanner](https://github.com/mmaitre314/picklescan/blob/75e60f2c02f3f1a029362e6f334e1921392dcf60/src/picklescan/scanner.py)).
