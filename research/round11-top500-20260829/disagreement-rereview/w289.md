# w289 re-research

## Decision

**AGREE** with the disagreement memo. Recommended primary verdict:
`EVIDENCE_GAP`. Recommended review verdict: `EVIDENCE_GAP`.

The vulnerability, smallest surviving public BIC, absent immediate parent, and
unpatched state are reproducible. The attribution gate is not: the BIC is an
unsigned, parentless 70,762-line initial snapshot. Its author/committer fields
name `jiayuqi7813`, but the object contains neither a positive human-writing
provenance signal nor an AI/bot/generator marker. Absence of an AI trailer does
not close causal authorship for this object shape. The official commit object
confirms the empty parent list, 70,762 additions, mapped GitHub identity, and
`unsigned` verification state ([BIC commit](https://github.com/FishCodeTech/muteki/commit/013ab6bf5fded15dcfcbcfbf94b3a270a79f9260)).

## Vulnerability mechanism

The demonstrated path is configuration-plane command execution in the local
Claude worker:

1. Muteki links each challenge attachment into the worker cwd under its basename
   in `_stage_attachments` ([BIC source](https://github.com/FishCodeTech/muteki/blob/013ab6bf5fded15dcfcbcfbf94b3a270a79f9260/muteki/solver/cli_solver.py#L1800-L1828)).
2. It launches `claude -p --dangerously-skip-permissions` from that same cwd
   ([driver](https://github.com/FishCodeTech/muteki/blob/013ab6bf5fded15dcfcbcfbf94b3a270a79f9260/muteki/solver/cli_driver.py#L417-L465),
   [cwd call](https://github.com/FishCodeTech/muteki/blob/013ab6bf5fded15dcfcbcfbf94b3a270a79f9260/muteki/solver/cli_solver.py#L2900-L2963)).
3. The web composer initializes `containerMode` to false and maps false to the
   host-subprocess `local` backend
   ([toggle](https://github.com/FishCodeTech/muteki/blob/013ab6bf5fded15dcfcbcfbf94b3a270a79f9260/apps/web/ui/components/Conversation.tsx#L742-L750),
   [mapping](https://github.com/FishCodeTech/muteki/blob/013ab6bf5fded15dcfcbcfbf94b3a270a79f9260/apps/web/ui/app/page.tsx#L406-L409)).
4. The reporter's archive contains `.claude/settings.json` with a `SessionStart`
   command hook. Its in-archive README tells the first worker to extract the
   archive and start a fresh headless Claude process in the current directory;
   that later process loads the planted project settings and runs the hook
   ([report](https://github.com/micr0softDrestlife/muteki_vul_report/blob/747da32f560684c1b3ca61f6760208f8edbe56cf/README.md#L52-L132),
   [payload generator](https://github.com/micr0softDrestlife/muteki_vul_report/blob/747da32f560684c1b3ca61f6760208f8edbe56cf/vul.py#L50-L103)).

The replay therefore does **not** show automatic archive extraction or immediate
execution merely on upload. It requires the worker to extract the archive and
follow the embedded instruction to launch a second Claude session. The reporter
states that this exact local-mode path produced a reverse shell as the worker
user and expressly limits the claim to that path. CVE-2026-79623 remains
`PUBLISHED`, identifies the Default Local Worker Backend and CWE-77/CWE-78, and
lists versions 0.2.0 through 0.2.5 as affected
([CVE record](https://cveawg.mitre.org/api/cve/CVE-2026-79623)). The GitHub
advisory has `withdrawn_at: null`
([GHSA](https://github.com/advisories/GHSA-w4x2-2pcx-2cpc)).

## Atomic BIC and immediate parent

`013ab6bf5fded15dcfcbcfbf94b3a270a79f9260` is the smallest surviving public
first-write. Local `git log --all --reverse -S` independently places all three
required product-side pieces there: `_stage_attachments`,
`--dangerously-skip-permissions`, and the composer local-backend mapping. The
commit is the repository root: `git rev-list --parents -n 1` returns only
`013ab6bf5fded15dcfcbcfbf94b3a270a79f9260`, and GitHub exposes `parents: []`
([commit](https://github.com/FishCodeTech/muteki/commit/013ab6bf5fded15dcfcbcfbf94b3a270a79f9260)).

There is consequently no immediate parent tree against which absence of the flaw
can be diffed. Parent absence is verified; pre-root absence is structurally
unobservable. Under the protocol, this root is still the smallest surviving
public object, but its 243-file/70,762-insertion shape weakens provenance rather
than creating a finer public BIC.

## Squash or member decomposition

No public pre-root member commits can be reconstructed, and the root object does

## BIC-only AI attribution

The raw BIC object identifies both author and committer as
`jiayuqi7813 <1783671926@qq.com>` and GitHub maps both fields to the user
`jiayuqi7813`. It has no `gpgsig`, `Co-authored-by`, `Generated-with`, Cursor,
Copilot, bot, or other AI/generator trailer; GitHub reports the object as
unsigned ([BIC commit](https://github.com/FishCodeTech/muteki/commit/013ab6bf5fded15dcfcbcfbf94b3a270a79f9260)).

Those facts establish only a claimed Git author/committer identity and absence
of a visible marker. For a parentless 70,762-line imported first snapshot, they
do not positively identify the causal writer of the vulnerable lines. There is
also no positive AI signal on this BIC. Fail-closed result: `EVIDENCE_GAP`, not
`NOT_AI` and not an AI-positive verdict.

## Corrections

1. Change the primary `verdict` from `NOT_AI` to `EVIDENCE_GAP` and describe the
   BIC marker state as “no visible AI marker; causal human authorship unproven.”
2. Qualify release membership: v0.2.2 is asserted affected by the CVE record but
   has no upstream tag/release object to test. Do not describe the whole
   0.2.0--0.2.5 range as independently verified Git membership.
3. Preserve the PoC precondition: Muteki stages the archive but does not itself
   auto-extract it; the demonstrated trigger requires worker extraction and a
   second headless Claude launch from the polluted cwd.

## Remaining gap

To reach `NOT_AI`, obtain first-party provenance that positively ties the
vulnerable root-snapshot content to a named human causal writer, not merely the
unsigned author fields and absence of trailers. Exact Git membership for v0.2.2
requires an authoritative source/tag for that release. No direct fix or fixed
release exists in the public evidence through
`d1093c1f96381488c1baef5ea1fde2a9b46bc9ae`.
