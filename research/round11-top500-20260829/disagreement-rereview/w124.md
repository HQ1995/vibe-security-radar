## Vulnerability mechanism

CVE-2026-42778 is `PUBLISHED`, not rejected or withdrawn. Apache's CNA record and release notice define affected versions as 2.1.0 through 2.1.11 and 2.2.0 through 2.2.6, fixed in 2.1.12 and 2.2.7. The reachable path is `ObjectSerializationDecoder.doDecode()` calling `IoBuffer.getObject(classLoader)` on incoming serialized data. `AbstractIoBuffer.getObject()` creates an `ObjectInputStream`; its `readClassDescriptor()` reads an attacker-controlled class name and executes `Class.forName(className, true, classLoader)` before the allowlist decision in `resolveClass()`. A disallowed class's static initializer can therefore execute before rejection. [CVE.org CNA record](https://cveawg.mitre.org/api/cve/CVE-2026-42778), [Apache MINA release/advisory](https://mina.apache.org/mina-project/#mina-227-2112-released-_posted-on-april-30-2026_), [GHSA record](https://github.com/advisories/GHSA-995c-6rp3-4m4x).

The unsafe `Class.forName(..., true, ...)` path is already present in the peeled 2.1.0 tag commit `d595254cb8c254204d794457d42219321a6a2306` and peeled 2.2.0 tag commit `079d4592943ff892504e11a331c4f6601b7a04ec`. Thus the 2024 allowlist additions cannot explain the advisory ranges beginning at 2.1.0 and 2.2.0; they only attempted, incompletely, to mitigate an older vulnerable path. [2.1.0 tag](https://github.com/apache/mina/tree/2.1.0), [2.2.0 tag](https://github.com/apache/mina/tree/2.2.0).

## Atomic BIC and immediate parent

The smallest public first writer is **Apache SVN r349422**, committed on 2005-11-28 by `trustin` with the message naming `DIRMINA-126 ByteBuffer.get/putObject()`. Its direct diff adds the `ObjectInputStream`, `getObject(ClassLoader)`, `Class.forName(className, true, classLoader)`, and `readObject()` path. The exact same file at immediate repository predecessor **r349421** has no `getObject()`, `ObjectInputStream`, or `Class.forName` path, so parent absence is verified. [r349422 file](https://svn.apache.org/repos/asf/!svn/rvr/349422/directory/network/trunk/src/java/org/apache/mina/common/ByteBuffer.java), [r349421 file](https://svn.apache.org/repos/asf/!svn/rvr/349421/directory/network/trunk/src/java/org/apache/mina/common/ByteBuffer.java).

The earliest local Git carrier, `f562722a84fb25ad233eb87f1e28e17ee0a8bd69` (parent `5a0b1f78b0507353aafdee7e3d367f5dabd88441`), is a 262-file, 33,505-line SVN move/import whose own message says “temp move of all mina subprojects”; it is not the BIC. Its `git-svn-id` is Apache r368798, whose copy source is `/directory/trunks/mina@368797`. Apache's SVN history follows the file through r359369 (copy from `/directory/network/trunk@359357`), r359371, r359423, r367153, and r368798, preserving the r349422 implementation into the Git carrier. [Git carrier](https://github.com/apache/mina/commit/f562722a84fb25ad233eb87f1e28e17ee0a8bd69), [Apache SVN r368798 carrier](https://svn.apache.org/repos/asf/!svn/rvr/368798/directory/trunks/mina-build/core/src/main/java/org/apache/mina/common/ByteBuffer.java).

## Squash or member decomposition

r349422 is not a move, revert, or later squash carrier. It is a direct SVN revision that modifies four paths for three named issues, and the vulnerable hunk is added directly in that revision; there is no finer public member to decompose. Its immediate predecessor is available and lacks the hunk.

The later copy/import revisions and Git commit `f562722a84fb25ad233eb87f1e28e17ee0a8bd69` are excluded as moves. The two 2024 allowlist commits are ordinary single-parent commits but are also excluded because their parents are already vulnerable: `691a9df5a0aff0dddeedc5181f6e5832ee90dcea` has parent `23e6ee17bae46bb8e7a76dd7aeb508ec89e76a25`, and `cdb59eb6131696a440870ab89ad0e20804eb5ca7` has parent `88cb55397c414c6d09ce2d085ce912ab4bf45bf3`. ## Direct fix or unpatched state

The direct fixes are branch-specific:

- 2.1.X: `ba8c355d82a010d677455df43b49725d21dbd07a`, parent `bfd80a05a69b6618947e0c6d74b598f663cdb288`; absent from 2.1.11 and an ancestor of 2.1.12.
- 2.2.X: `cca24d646c898adf7e01a765ebf6d677cc02b696`, parent `b967f0b924d7516c4496832195e046b2a36d0847`; absent from 2.2.6 and an ancestor of 2.2.7.

Both patches insert the `acceptMatchers` decision before `Class.forName(className, true, classLoader)` in `readClassDescriptor()` and before any fallback class load in `resolveClass()`. The call still uses `initialize=true`; the security change is that a disallowed name is rejected before that call. Neither commit has an associated GitHub pull request; the exact first-party commit objects are the direct evidence. [2.1.X fix](https://github.com/apache/mina/commit/ba8c355d82a010d677455df43b49725d21dbd07a), [2.2.X fix](https://github.com/apache/mina/commit/cca24d646c898adf7e01a765ebf6d677cc02b696).
