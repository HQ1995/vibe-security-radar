# w387 re-research

## Decision

**AGREE** with the disagreement memo. Recommended primary verdict: **NOT_AI**. Recommended review verdict: **CONFIRMED**, with a field-only correction that replaces `remaining_gap: null` with the public 1.3.x release-object gap described below. The gap prevents complete release-membership replay, but it does not break the vulnerability, atomic-BIC, immediate-parent, direct-fix, or BIC-only authorship closures.

## Vulnerability mechanism

The CNA record is `PUBLISHED`, classifies this as CWE-502, and says an attacker-controlled paginated GraphQL request can reach unsafe deserialization and RCE when a Connection field is exposed and a usable classpath gadget is present ([CVE-2026-41699](https://cveawg.mitre.org/api/cve/CVE-2026-41699); [Spring advisory](https://spring.io/security/cve-2026-41699)).

The vulnerable `v2.0.3` tree is commit `c2a930280462e12abc003a38ebc54997c4f283be`. Source replay gives this complete path:

1. `SubrangeMethodArgumentResolver.resolveArgument` and `RepositoryUtils.getScrollSubrange` take the GraphQL `after` or `before` argument and pass it to `CursorStrategy.fromCursor`.
2. `EncodingCursorStrategy.fromCursor` Base64-decodes attacker input and delegates it.
3. `ScrollPositionCursorStrategy.fromCursor` recognizes the keyset prefix and sends the remaining cursor JSON to `JsonKeysetCursorStrategy.fromCursor`.
4. That method invokes the configured Jackson decoder for `Map<String,Object>`. Both Jackson 3 and Jackson 2 customizers in this tag activate `NON_FINAL` default typing with `allowIfBaseType(Map.class)`. Once the declared Map base is accepted, attacker-supplied subtype metadata can select a Map implementation; a suitable Map gadget on the application classpath can therefore run during construction or deserialization.

This reproduces the advisory mechanism from the affected release tree rather than inferring it from the advisory title ([`v2.0.3`](https://github.com/spring-projects/spring-graphql/releases/tag/v2.0.3); [GitHub advisory](https://github.com/advisories/GHSA-px92-q6rc-6mwv)).

## Atomic BIC and immediate parent

The atomic public BIC is `577014f4f123604b33f07d907a10a655ed6e6cd9` ([official commit](https://github.com/spring-projects/spring-graphql/commit/577014f4f123604b33f07d907a10a655ed6e6cd9)). Path-scoped `git log -S` independently makes it the first object to add both `allowIfBaseType(Map.class)` and `activateDefaultTyping` to `JsonKeysetCursorStrategy.java`. Its target-file diff adds the custom mapper, broad Map base-type permission, and default typing together; this is the unsafe mechanism itself, not a later move or copy.

The immediate parent is `d717e80cb9bfb088e210c13dbff194eb0b7d7faf` ([official parent object](https://github.com/spring-projects/spring-graphql/commit/d717e80cb9bfb088e210c13dbff194eb0b7d7faf)). Its tree contains the same `fromCursor` Map-decoding sink, but no `BasicPolymorphicTypeValidator`, `allowIfBaseType`, or `activateDefaultTyping`. The earlier pagination first-write `104eccb4d9a657784bdefecfda28b288f083c39d` likewise decodes Map JSON without polymorphic typing ([pagination commit](https://github.com/spring-projects/spring-graphql/commit/104eccb4d9a657784bdefecfda28b288f083c39d)). Immediate-parent absence is therefore verified.

## Squash or member decomposition

`577014f4f123604b33f07d907a10a655ed6e6cd9` has exactly one parent, directly changes the vulnerable file, and is the smallest surviving public object that first writes the unsafe block. Its message closes issue 684; the official issue identifies the motivating non-simple keyset round-trip problem, is authored by `rstoyanchev`, has no linked pull request, and is closed by the commit ([issue 684](https://github.com/spring-projects/spring-graphql/issues/684)). There is no merge/squash aggregate or finer public member to decompose.

Later object `6ce4e53e44917e2560fc86eb437fbca5b0ffb491` merely reinstates a Jackson 2 compatibility copy of the existing broad rule; it is not the origin ([official commit](https://github.com/spring-projects/spring-graphql/commit/6ce4e53e44917e2560fc86eb437fbca5b0ffb491)).

- `v1.4.0` = `b2d00cd888f7943166b65fcebe49e0bfd780bf4f` and `v1.4.5` = `3100184962cde4dbe6340ff7ea5087dceef29c7b`: affected; `v1.4.6` = `1209172768d8034f03774ec6ce54602df87bf3ef`: contains fix `2be20ad0a655d952bdeaeaa1eeea95bc3d130f34` and the explicit subtype allowlist ([`v1.4.6`](https://github.com/spring-projects/spring-graphql/releases/tag/v1.4.6)).
- `v2.0.0` = `6aa2cb03bcc9de5c0702af90c61c7814ed2f7ebd` and `v2.0.3` = `c2a930280462e12abc003a38ebc54997c4f283be`: affected; `v2.0.4` = `41dc07979e9fb5f32891f23802e7efc3273b7f27`: contains Jackson 3 fix `e01cd34dd7b29a08559e1276487e2b3371f42963` ([`v2.0.4`](https://github.com/spring-projects/spring-graphql/releases/tag/v2.0.4)).
- `v2.0.4` still contains the broad rule in its Jackson 2 fallback. `v2.0.5` = `b86e6e91e7fb61fd3ae72992238f9d3edb13cf62` contains follow-up `cb45b282eba10ff2af5c928acec1efb45e08604c`, which applies the allowlist to that fallback too ([`v2.0.5`](https://github.com/spring-projects/spring-graphql/releases/tag/v2.0.5)).

The vendor lists affected `2.0.0`–`2.0.3`, `1.4.0`–`1.4.5`, and `1.3.8 and earlier`, with OSS fixes `2.0.4` and `1.4.6` and enterprise-only `1.3.9` ([Spring advisory](https://spring.io/security/cve-2026-41699)). The CNA structured range instead begins the 1.3 line at `1.3.0`; independently, the public `v1.2.0` tree already contains the BIC and broad rule ([CVE record](https://cveawg.mitre.org/api/cve/CVE-2026-41699)).

## Direct fix or unpatched state

`e01cd34dd7b29a08559e1276487e2b3371f42963` directly replaces the Jackson 3 `allowIfBaseType(Map.class)` rule with `allowIfSubType` entries for `LinkedHashMap`, `HashMap`, and `java.util.Collections` implementations ([official commit](https://github.com/spring-projects/spring-graphql/commit/e01cd34dd7b29a08559e1276487e2b3371f42963); [issue 1445](https://github.com/spring-projects/spring-graphql/issues/1445)). The 1.4.x backport `2be20ad0a655d952bdeaeaa1eeea95bc3d130f34` makes the same direct change ([official commit](https://github.com/spring-projects/spring-graphql/commit/2be20ad0a655d952bdeaeaa1eeea95bc3d130f34); [issue 1446](https://github.com/spring-projects/spring-graphql/issues/1446)).

The Jackson 2 fallback is directly corrected by `cb45b282eba10ff2af5c928acec1efb45e08604c` ([official commit](https://github.com/spring-projects/spring-graphql/commit/cb45b282eba10ff2af5c928acec1efb45e08604c); [issue 1496](https://github.com/spring-projects/spring-graphql/issues/1496)). GitHub-advisory reference `5579b6eca045126a27405b4cb1ae1f38d7577cb7` changes GraphQL variable nullness files and does not touch the cursor strategy, so it is not a direct fix ([official commit](https://github.com/spring-projects/spring-graphql/commit/5579b6eca045126a27405b4cb1ae1f38d7577cb7)).

No public `v1.3.9` tag or fix object is available to replay the enterprise-only 1.3.x remediation.

## Corrections

1. Replace the primary's `remaining_gap: null` with the exact public-release gap below.
2. Treat release verification separately from causal verification: the missing `v1.3.8` and enterprise `v1.3.9` objects prevent complete 1.3.x membership replay, but do not justify changing the reproduced **NOT_AI** verdict to `EVIDENCE_GAP`.
3. Preserve the qualification that advertised fixed release `v2.0.4` fixes the Jackson 3 path while its Jackson 2 compatibility path retains the broad rule until `v2.0.5`.

## Remaining gap

Neither the supplied clone nor exact `git ls-remote` queries expose `refs/tags/v1.3.8` or `refs/tags/v1.3.9`. The Spring advisory is authoritative for affected `1.3.8 and earlier` and enterprise-only fix `1.3.9`, but the exact affected `v1.3.8` tree and enterprise fixed tree/patch cannot be independently replayed from public Git. This is a release-membership evidence gap only.
