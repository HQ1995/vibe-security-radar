# w180 re-research

## Decision

**AGREE** with the disagreement memo's conditional conclusion: no reachable unsanitized sink was established for the advisory's stated v5.13.0 portal/PDF mechanism. Recommended primary verdict: `EVIDENCE_GAP`. Recommended review verdict: `CORRECTION_REQUIRED`.

The official advisory and CVE record remain published and claim affected versions `< 5.13.4`, but the first-party v5.13.0 tree contradicts a decisive premise of their narrative: both named render paths already call `Purify::clean()`. That conflict prevents `NOT_AI`; it does not by itself justify `FALSE_POSITIVE` because the CVE is `PUBLISHED` and the advisory is not withdrawn ([repository advisory](https://github.com/invoiceninja/invoiceninja/security/advisories/GHSA-98wm-cxpw-847p), [CVE record](https://cveawg.mitre.org/api/cve/CVE-2026-33628)).

## Vulnerability mechanism

The claimed source is an authenticated invoice create/update request. In v5.13.0, `StoreInvoiceRequest` routes `line_items` through `cleanItems()`, whose `cleanLineItem()` applies the case-sensitive token denylist `</sc`, `onerror`, `prompt(`, and `alert(` to `notes`, `product_key`, and four custom fields ([request lines 126-129](https://github.com/invoiceninja/invoiceninja/blob/v5.13.0/app/Http/Requests/Invoice/StoreInvoiceRequest.php#L126-L129), [denylist lines 77-82](https://github.com/invoiceninja/invoiceninja/blob/v5.13.0/app/Utils/Traits/CleanLineItems.php#L77-L82)). Payloads such as `<svg onload=confirm(document.domain)>` bypass that input denylist and can be stored. Conversely, the advisory's displayed reproduction payload, `<img src=x onerror=alert(document.cookie)>`, contains two denied tokens and therefore does not itself replay a denylist bypass in that tree.

The claimed source-to-sink execution did not replay structurally in the affected tag. The v5.13.0 client-portal HTML viewer calls `App\Services\Pdf\Purify::clean()` on both product and service notes ([portal product line 81](https://github.com/invoiceninja/invoiceninja/blob/v5.13.0/resources/views/portal/ninja2020/components/html-viewer.blade.php#L81), [portal service line 123](https://github.com/invoiceninja/invoiceninja/blob/v5.13.0/resources/views/portal/ninja2020/components/html-viewer.blade.php#L123)). `PdfService::getHtml()` also cleans both JSON-design HTML and the completed DOM before PDF generation ([v5.13.0 lines 127-146](https://github.com/invoiceninja/invoiceninja/blob/v5.13.0/app/Services/Pdf/PdfService.php#L127-L146)). The sanitizer removes disallowed elements, removes non-allowlisted attributes, and restricts `href`/`src`; the relevant default is `DISABLE_PURIFY_HTML=false` ([sanitizer](https://github.com/invoiceninja/invoiceninja/blob/v5.13.0/app/Services/Pdf/Purify.php#L251-L434), [default](https://github.com/invoiceninja/invoiceninja/blob/v5.13.0/config/ninja.php#L268)). No first-party object examined supplied a concrete bypass of those output controls.

## Atomic BIC and immediate parent

`192722b7a47556bef14e0460df25d71ee570a73a` is not an atomic BIC. It adds `str_replace("</", "<-")` to line-item notes and product keys, but its sole immediate parent `2c253710111b9189524e273e8416650088fec425` accepts the same fields without any such filter. The parent is therefore not proven non-vulnerable; the child adds a partial mitigation rather than first writing the vulnerable behavior ([candidate diff](https://github.com/invoiceninja/invoiceninja/commit/192722b7a47556bef14e0460df25d71ee570a73a), [immediate parent](https://github.com/invoiceninja/invoiceninja/commit/2c253710111b9189524e273e8416650088fec425)).

`1c9450a6e4eac9b90aacc70ec6ef1f010681e904` is a genuine historical safe-to-unsafe transition for the portal template: it changes product/service notes from escaped `{{ ... }}` to raw `{!! ... !!}`, while immediate parent `a7d3424720102f3625423f9ccc9de1b475af3db8` is escaped ([transition](https://github.com/invoiceninja/invoiceninja/commit/1c9450a6e4eac9b90aacc70ec6ef1f010681e904), [parent](https://github.com/invoiceninja/invoiceninja/commit/a7d3424720102f3625423f9ccc9de1b475af3db8)). It still cannot be assigned as this advisory's BIC: `e9493d597b8311f9e7855d5b8b93ec399536cfea` later wraps both raw note expressions in `Purify::clean()` and is already an ancestor of v5.13.0 ([portal mitigation](https://github.com/invoiceninja/invoiceninja/commit/e9493d597b8311f9e7855d5b8b93ec399536cfea)). The actual advisory BIC and non-vulnerable immediate parent therefore remain unresolved.

## Squash or member decomposition

There is no squash aggregate to decompose for the rejected candidate. `192722b7a47556bef14e0460df25d71ee570a73a` is a single-parent public member of eight-commit PR #9291; the merge object is `a72058525e4c934a2c7bc443ad13aef2a871a7da`, not the candidate ([PR #9291](https://github.com/invoiceninja/invoiceninja/pull/9291), [merge object](https://github.com/invoiceninja/invoiceninja/commit/a72058525e4c934a2c7bc443ad13aef2a871a7da)). `1c9450a6e4eac9b90aacc70ec6ef1f010681e904` is likewise a single-parent public commit, but the later portal mitigation prevents it from closing the affected-release mechanism. Member decomposition therefore does not repair the missing causal BIC.

## Affected and fixed releases

The CNA record says `< 5.13.4` affected and the repository advisory says `5.13.4` patched ([CVE record](https://cveawg.mitre.org/api/cve/CVE-2026-33628), [advisory](https://github.com/invoiceninja/invoiceninja/security/advisories/GHSA-98wm-cxpw-847p)). Local tag replay resolves v5.13.0 to `936ff9cf3326b2774bc8dc0aa8fa1eca11ce5b20`, v5.13.3 to `6d3480fc09174971528111a69859ae644c052799`, and v5.13.4 to `5ff2095eafe4a891807e4be7a91e1bfb8e56269c` ([v5.13.0](https://github.com/invoiceninja/invoiceninja/commit/936ff9cf3326b2774bc8dc0aa8fa1eca11ce5b20), [v5.13.3](https://github.com/invoiceninja/invoiceninja/commit/6d3480fc09174971528111a69859ae644c052799), [v5.13.4](https://github.com/invoiceninja/invoiceninja/commit/5ff2095eafe4a891807e4be7a91e1bfb8e56269c)).

The relevant `CleanLineItems.php`, portal viewer, `PdfService.php`, and `Purify.php` blobs are identical between v5.13.0 and v5.13.3. `b81a3fc302573fc4a53d61e8537dd19154ce1091` is absent from both affected tag histories and present in v5.13.4 through PR #11811. This verifies the published release membership, but release membership alone does not supply the missing executable sink or BIC ([PR #11811](https://github.com/invoiceninja/invoiceninja/pull/11811)).

## Direct fix or unpatched state

The vendor-cited hardening commit is `b81a3fc302573fc4a53d61e8537dd19154ce1091`: it replaces the four-token input denylist with `Purify::clean($item[$field], true)` and adds `XssSanitizationTest` cases for reported bypass payloads ([fix commit](https://github.com/invoiceninja/invoiceninja/commit/b81a3fc302573fc4a53d61e8537dd19154ce1091)). Its immediate follow-up `fdcec3a4eb180c09d1760e89962874c4289cfee8` removes a temporary character gate and logging while retaining input purification ([follow-up](https://github.com/invoiceninja/invoiceninja/commit/fdcec3a4eb180c09d1760e89962874c4289cfee8)). Both are individual members of PR #11811 before merge `5ff2095eafe4a891807e4be7a91e1bfb8e56269c`.

This is a relevant defense-in-depth fix, but it is not causally closed as the direct fix for the claimed portal/PDF execution: the new tests exercise `cleanItems()` and sanitizer output, not execution through an affected-release sink, while those two sinks already purify at v5.13.0. Keep `fix_sha=b81a3fc302573fc4a53d61e8537dd19154ce1091` as the advisory-cited fix object, but set `direct_fix_sha=null` until a vulnerable pre-fix path and its elimination are demonstrated.

The raw commit objects for rejected candidate `192722b7a47556bef14e0460df25d71ee570a73a` and historical portal transition `1c9450a6e4eac9b90aacc70ec6ef1f010681e904` both name David Bomba `<turbo124@gmail.com>` as author and committer and contain only their ordinary subjects, with no `Co-Authored-By`, generator, Copilot, Cursor, ChatGPT, Claude, or bot marker ([candidate object](https://github.com/invoiceninja/invoiceninja/commit/192722b7a47556bef14e0460df25d71ee570a73a), [historical transition object](https://github.com/invoiceninja/invoiceninja/commit/1c9450a6e4eac9b90aacc70ec6ef1f010681e904)). Those are candidate-object facts, not BIC-object attribution; they cannot support `NOT_AI`. Recommended `ai_marker=null`.

## Remaining gap

Reproduce an executable line-item payload on an affected release under the documented default `DISABLE_PURIFY_HTML=false`, identifying either a reachable render path that omits `Purify::clean()` or an exact bypass of the v5.13.0 sanitizer. Then trace that mechanism to the smallest public safe-parent-to-vulnerable-child transition and inspect AI signals on that BIC object only. Static source replay closed the named portal/PDF routes against the report payload family, but a runtime application/browser reproduction was unavailable in this clone environment (`php` is not installed), so absence of a different route or sanitizer bypass is not asserted.
