# w115 re-research

## Decision

**DISAGREE** with the disagreement memo. The memo accepted the independent review's `EVIDENCE_GAP` because the atomic origin of ZDRES-233 was supposedly hidden behind import commit `f562722a84fb25ad233eb87f1e28e17ee0a8bd69`. That Git object is only an import, but its own `git-svn-id` and Apache SVN copy history lead to the actual public first-write, Apache SVN r349422, whose immediate predecessor r349421 lacks the object-deserialization API. The BIC is therefore recoverable.

- Recommended primary verdict: **`NOT_AI`**.
- Recommended review verdict: **`CORRECTION_REQUIRED`**, not `EVIDENCE_GAP`: the primary verdict is supported, but its single-SHA origin/fix narrative conflates two mechanisms and its fixed-release account is wrong for the proxy bypass.

## Vulnerability mechanism

The Apache CNA record is `PUBLISHED` and defines two distinct CWE-502 mechanisms under CVE-2026-47065.

1. **ZDRES-232 (proxy allow-list bypass).** `ObjectSerializationDecoder.doDecode()` installs `acceptMatchers` on the `IoBuffer`, then calls `getObject(classLoader)`. The anonymous `ObjectInputStream` filtered ordinary descriptors in `readClassDescriptor()` / `resolveClass()` but did not override `resolveProxyClass(String[])`. A `TC_PROXYCLASSDESC` therefore dispatched to the JDK default proxy resolver, which loaded every named interface and constructed a proxy without consulting MINA's accept list. The direct fix adds an override that checks every interface before `Class.forName(..., false, classLoader)`.
2. **ZDRES-233 (premature static initialization).** For a type-1 descriptor, MINA read an attacker-supplied class name, called `Class.forName(className, true, classLoader)`, and then `ObjectStreamClass.lookup(clazz)`. Thus merely naming an allow-listed class could execute its `<clinit>` before an instance was constructed. Changing `true` to `false` was insufficient because `ObjectStreamClass.lookup(clazz)` also initializes the class; the complete fix delegates descriptor parsing to `super.readClassDescriptor()` after the allow-list check.

This was replayed, not inferred from the prior reviews. Apache's `ClinitDescriptorTest` from commit `409171daa076f4bb5ab2e2e54b312bdcafd8c235` was run against the immediately preceding partial-fix tree `850592195d92acbce1d8be9b341e487b4361512c` with `mvn -Denforcer.skip=true -pl mina-core -Dtest=ClinitDescriptorTest test`: two tests ran and `truncatedDescriptorMustNotInitializeAllowListedClass` failed because `<clinit>` executed. The same command on tag 2.2.8 passed both tests. The proxy path is independently explicit in the CNA mechanism and in the direct-fix diff.

Sources: [Apache CNA record](https://cveawg.mitre.org/api/cve/CVE-2026-47065), [Apache release advisory](https://lists.apache.org/thread/y7xj1bl8qo47p9bktb11hg5v6k1d4dyj), [partial 2.2.x fix](https://github.com/apache/mina/commit/850592195d92acbce1d8be9b341e487b4361512c), [complete ZDRES-233 fix and test](https://github.com/apache/mina/commit/409171daa076f4bb5ab2e2e54b312bdcafd8c235).

## Atomic BIC and immediate parent

The advisory must be decomposed by mechanism.

**ZDRES-232 has one branch-local first-write per maintained line:**

- 2.2.x: `691a9df5a0aff0dddeedc5181f6e5832ee90dcea`, immediate parent `23e6ee17bae46bb8e7a76dd7aeb508ec89e76a25`.
- 2.1.x: `cdb59eb6131696a440870ab89ad0e20804eb5ca7`, immediate parent `88cb55397c414c6d09ce2d085ce912ab4bf45bf3`.
- 2.0.x: `834396355766e0c8f6bbf0493d4588b3fa9d347d`, immediate parent `e1eaa679167cd099305ec49fb6f8ca095836b852`.

Each parent has no `acceptMatchers`; each child first-writes the deserialization accept list and the incomplete ordinary-class filtering while still lacking `resolveProxyClass`. The 2.2.x object predates the two maintenance-line ports and is the earliest Git BIC for this mechanism.

**ZDRES-233:** the local Git blame stops at import/move `f562722a84fb25ad233eb87f1e28e17ee0a8bd69` (parent `5a0b1f78b0507353aafdee7e3d367f5dabd88441`), but that object's `git-svn-id` points to ASF revision 368798. The official SVN log follows the copy chain through r368798, r367153, r359423, r359371, r359369 and back to `/directory/network/trunk`. There, **r349422** (2005-11-28, author `trustin`) is the atomic revision that added `ByteBuffer.getObject()` / `putObject()` and first wrote `Class.forName(className, true, classLoader)`; exact predecessor **r349421** contains no `getObject`, `readClassDescriptor`, or that `Class.forName` call. This is parent absence, not merely blame to an import.

Apache's Git conversion does not expose r349422 as a 40-hex object, so inventing a SHA would be wrong. The exact first-party object is the immutable SVN revision; all Git objects in this report are given as full 40-hex identifiers.

Sources: [2.2.x ZDRES-232 BIC](https://github.com/apache/mina/commit/691a9df5a0aff0dddeedc5181f6e5832ee90dcea), [2.1.x BIC](https://github.com/apache/mina/commit/cdb59eb6131696a440870ab89ad0e20804eb5ca7), [2.0.x BIC](https://github.com/apache/mina/commit/834396355766e0c8f6bbf0493d4588b3fa9d347d), [SVN r349422 source](https://svn.apache.org/repos/asf/!svn/bc/349422/directory/network/trunk/src/java/org/apache/mina/common/ByteBuffer.java), [SVN r349421 parent source](https://svn.apache.org/repos/asf/!svn/bc/349421/directory/network/trunk/src/java/org/apache/mina/common/ByteBuffer.java).

## Squash or member decomposition

`f562722a84fb25ad233eb87f1e28e17ee0a8bd69` is disqualified as a BIC because it is the Git rendering of an SVN directory-copy aggregate. It is nevertheless a usable routing object: ASF r368798 records `core` as copied from `/directory/trunks/mina@368797`, and the SVN log preserves the earlier copy ancestry down to r349422.

SVN r349422 is not a move or import. It is a normal feature revision modifying `ByteBuffer.java`, `ByteBufferProxy.java`, and `ByteBufferTest.java`, and adding `BufferDataException.java`; its log message expressly identifies DIRMINA-126 (`ByteBuffer.get/putObject()`). That is the smallest public object which first writes the ZDRES-233 path.

The three 2024 ZDRES-232 commits are large single-parent feature commits, not merges or reverts. No finer public member exists inside any of those objects; they are therefore the smallest permitted branch-local BICs even though each also carries dependency or formatting work.

Sources: [Git import object](https://github.com/apache/mina/commit/f562722a84fb25ad233eb87f1e28e17ee0a8bd69), [SVN r349422 implementation](https://svn.apache.org/repos/asf/!svn/rvr/349422/directory/network/trunk/src/java/org/apache/mina/common/ByteBuffer.java).

## Affected and fixed releases

The repository tags separate the two mechanisms more precisely than the published range:

- ZDRES-232 first appears in 2.2.4 (`691a9df5a0aff0dddeedc5181f6e5832ee90dcea` is absent from 2.2.3 and present from 2.2.4), 2.1.10 (`cdb59eb6131696a440870ab89ad0e20804eb5ca7`), and 2.0.27 (`834396355766e0c8f6bbf0493d4588b3fa9d347d`). Earlier releases in the CNA's broad ranges can still be affected by ZDRES-233, but they do not contain this allow-list-bypass mechanism because they have no allow list.
- 2.2.8 is the first 2.2.x tag containing both `850592195d92acbce1d8be9b341e487b4361512c` and `409171daa076f4bb5ab2e2e54b312bdcafd8c235`; 2.2.7 contains neither. The peeled tag commits are 2.2.7=`a2fa7504ddff446a6cb93862f4517a6ca74b07cd` and 2.2.8=`4e0e0aeea8580328a2794b1157a9acc642da15fb`.
- 2.1.13 contains ZDRES-233 fix `f2d110bccb7ace38701e44c122832e085f9c455b` but no `resolveProxyClass`; 2.1.14 is also proxy-unpatched. The first tag containing both fixes is 2.1.15 via `3166d262de1e7027a360ebb85732dbf861b1eea7`. Peeled commits: 2.1.13=`298d4259ca6683e01c19b41735eebf19b36d5f89`, 2.1.14=`6c0c5969b035655e5376cb29e8591e4f52537593`, 2.1.15=`fa71cbb56867dc1fb94ea76ff007f2e188206d3a`.
- 2.0.29 contains ZDRES-233 fix `d0456f6390b3a275e5e528b405ab3725ad8c8394` but no `resolveProxyClass`; 2.0.30 is also proxy-unpatched. The first tag containing both fixes is 2.0.31 via `833f3db173526e3d25f053cf81e37053b0466f2a`. Peeled commits: 2.0.29=`0b8a0e5002a03b8b732a45edef02059648d8f8e4`, 2.0.30=`0bc2ac1da15772afb3351737390354c4eb12ccfc`, 2.0.31=`ea4d278c6ce02e69a4410cb041cf64e3f3c47d70`.

Therefore the CNA/GHSA statements that 2.1.13 and 2.0.29 fully fix CVE-2026-47065 are contradicted by the released trees. The later proxy-fix subjects explicitly say that the CVE fix had not been backported by mistake.

## Direct fix or unpatched state

There is no valid advisory-wide single `direct_fix_sha`; closure is mechanism- and branch-specific.

- 2.2.x ZDRES-232 direct fix: `850592195d92acbce1d8be9b341e487b4361512c` adds the missing proxy-interface checks.
- 2.2.x ZDRES-233: `850592195d92acbce1d8be9b341e487b4361512c` changes `initialize=true` to `false`, but remains vulnerable through `ObjectStreamClass.lookup(clazz)` as the failed replay demonstrates. `409171daa076f4bb5ab2e2e54b312bdcafd8c235` is the completing direct fix, replacing that lookup with `super.readClassDescriptor()` and adding the regression test.
- 2.1.x: `f2d110bccb7ace38701e44c122832e085f9c455b` fixes ZDRES-233; `3166d262de1e7027a360ebb85732dbf861b1eea7` later fixes ZDRES-232.
- 2.0.x: `d0456f6390b3a275e5e528b405ab3725ad8c8394` fixes ZDRES-233; `833f3db173526e3d25f053cf81e37053b0466f2a` later fixes ZDRES-232.

GitHub's commit-to-PR endpoint returns an empty array for all four proxy/2.2 completion commits, so there is no first-party PR object to substitute for these direct commit objects.

## BIC-only AI attribution

The attribution is evaluated only on the reconstructed BIC objects.

- `691a9df5a0aff0dddeedc5181f6e5832ee90dcea`, `cdb59eb6131696a440870ab89ad0e20804eb5ca7`, and `834396355766e0c8f6bbf0493d4588b3fa9d347d` all name Emmanuel Lecharny (`elecharny@apache.org`) as author and committer. Their raw commit objects contain ordinary human-written subjects and no `Co-Authored-By`, `Generated-with`, bot identity, generator marker, or AI marker.
- Apache SVN r349422 names ASF account `trustin` as the author on 2005-11-28. The ASF committer index maps `trustin` to **Trustin Lee**. The revision metadata contains a concrete DIRMINA issue summary and no bot/generator/AI marker.

Every mechanism's smallest public BIC therefore has a named human writer and no positive AI signal on the BIC itself. This satisfies `NOT_AI`; the import object and later fixes are irrelevant to BIC-only attribution.

## Corrections

1. Keep `verdict=NOT_AI`; do not replace it with `EVIDENCE_GAP`.
2. Replace the single-origin narrative with two mechanism records: ZDRES-232's three branch-local 2024 Git BICs and ZDRES-233's ASF SVN r349422 BIC with r349421 as its verified predecessor.
3. Remove `2f8af59602e5ca5185c7f580b9ddff28a89de247` as any claimed ZDRES-233 origin; its parent already contains the dangerous call.
4. Do not use import `f562722a84fb25ad233eb87f1e28e17ee0a8bd69` as the BIC. Use its SVN copy ancestry to reach r349422.
5. Replace the single `fix_sha` / `direct_fix_sha` with the per-mechanism, per-branch fix sets above.
6. Correct full-fix releases to 2.2.8, 2.1.15, and 2.0.31. Record 2.1.13/2.0.29 as ZDRES-233-only fixes and 2.1.14/2.0.30 as still proxy-unpatched.
7. Narrow the mechanism-specific ZDRES-232 introduction to 2.2.4, 2.1.10, and 2.0.27; do not confuse the broader two-mechanism CVE range with the proxy-bypass range.

## Remaining gap

There is no remaining causal or BIC-attribution gap. Two representational/publication issues remain:

- the current single-SHA record shape cannot faithfully encode an SVN BIC plus three branch-local Git BICs and multiple direct fixes;
- the Apache CNA/GHSA fixed-version metadata has not been reconciled with the repository fact that 2.1.13, 2.1.14, 2.0.29, and 2.0.30 retain ZDRES-232.

Neither issue blocks `NOT_AI`; both require field correction rather than fail-closed authorship grading.
