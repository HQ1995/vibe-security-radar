## Vulnerability mechanism

The published CNA record describes unauthenticated time-based blind SQL injection through `geoquery`, caused by insufficient escaping and lack of query preparation through version 1.0.3 ([CVE-2026-6230 record](https://cveawg.mitre.org/api/cve/CVE-2026-6230); [GHSA-cqgm-j57m-cj34](https://github.com/advisories/GHSA-cqgm-j57m-cj34)). The repository reproduces the complete path:

1. The readable collection-items REST route invokes `get_items`; `get_items_permissions_check` returns true for a readable collection (and also when no collection object is resolved).
2. `get_items` copies attacker-controlled `$request['geoquery']` directly into `$args['geoquery']`.
3. `GeoCoordinate_Helper::posts_where` reads that value and inserts `key`, `point`, `distance`, and `polygon` directly into `meta_key`, `ST_Distance_Sphere`, `point(...)`, and `ST_GEOMFROMTEXT('POLYGON(...)')` SQL fragments without `$wpdb->prepare`.

Those source and sink lines are present in the vulnerable [1.0.3 REST controller](https://github.com/tainacan/tainacan/blob/1.0.3/src/classes/api/endpoints/class-tainacan-rest-items-controller.php) and [1.0.3 helper](https://github.com/tainacan/tainacan/blob/1.0.3/src/views/admin/components/metadata-types/geocoordinate/class-tainacan-geocoordinate-helper.php).
