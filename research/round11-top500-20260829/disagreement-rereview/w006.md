# w006 re-research

## Decision

**PARTIAL** with the disagreement memo. The memo is right that the causal classification is stable: the recommended primary verdict remains **`AI_ROOT_CAUSE`**. It is also right that this is a release-range correction rather than a verdict flip. I do not agree that the review can be closed as confirmed without correction: the recommended review verdict remains **`CORRECTION_REQUIRED`**, narrowly limited to the affected-release wording. The CNA's `2.0.0` lower bound conflicts with repository history, and the MCP source-to-sink is first code-proven only in a still later tag.

## Vulnerability mechanism

The live [CVE-2026-77068 record](https://www.cve.org/CVERecord?id=CVE-2026-77068) and [vendor advisory GHSA-6h4x-896x-fw5m](https://github.com/n8n-io/n8n/security/advisories/GHSA-6h4x-896x-fw5m) describe authenticated `global:member` RCE through the workflow-SDK schema loader used by MCP node-schema validation.

The repository source-to-sink replays that mechanism. Commit [`166eb85509b2409eb5e59f37dea96c849d0df790`](https://github.com/n8n-io/n8n/commit/166eb85509b2409eb5e59f37dea96c849d0df790) added `validate_node_config`: its input schema accepts arbitrary `nodes[].type`, and its handler passes `node.type` directly to `validateNodeConfig`. In affected tag `n8n@2.25.1` (tag commit `d1c8049ddb5dd8013cca746e450c5933b8403462`), `nodeTypeToPathComponents` only removes a leading `@n8n/` and splits on `.`. `tryLoadSchemaForNodeType` then uses the resulting `pkg` and `nodeName` in `path.join(baseDir, 'nodes', ...)`, and `tryLoadSchemaModule` executes `require(schemaPath)`. There is no separator, NUL, `.`/`..`, realpath, or root-containment validation. An attacker-controlled type can therefore traverse outside the schema `nodes` root and make the MAIN process load a resolvable module outside that root. The direct-fix regression tests independently encode the same replay with `nodeType = 'x.' + '../'.repeat(steps)`, plus directory- and leaf-symlink escapes, in [`ca3d42d8386515cd9f044377a15a632cd09b62f0`](https://github.com/n8n-io/n8n/commit/ca3d42d8386515cd9f044377a15a632cd09b62f0).

## Atomic BIC and immediate parent

The atomic BIC is [`6d88b9e1e9f24901985b1fb4e4200f18bd550e1b`](https://github.com/n8n-io/n8n/commit/6d88b9e1e9f24901985b1fb4e4200f18bd550e1b), a public, signed, single-parent PR member. It creates `packages/@n8n/workflow-sdk/src/validation/schema-validator.ts` as a 273-line added file and first writes all of the root-cause operations: attacker-derived `pkg`/`nodeName`, `path.join(..., pkg, nodeName, ...)`, and `require(schemaPath)`. It also wires workflow `node.type` into `validateNodeConfig`.

Its immediate parent is `d5f2772381a8d91592fd47845fef5422f80cf9d9`. That object exists, but the new `schema-validator.ts` path does not; a parent-tree search has no workflow-SDK `nodeTypeToPathComponents`, `loadSchema`, or `tryLoadSchemaModule` mechanism. Thus the mechanism is absent in the immediate parent, while `introducer_parent_absent=false` correctly means the parent object itself is available.

## Squash or member decomposition

[PR #24535](https://github.com/n8n-io/n8n/pull/24535) landed as the one-parent GitHub squash [`9729c2a5da7b59fdbf62b95c100e085a2c2daa4d`](https://github.com/n8n-io/n8n/commit/9729c2a5da7b59fdbf62b95c100e085a2c2daa4d), whose parent is `ba48c922c74c7c2c6627af15d8141dd3ab85063c`. That parent lacks `schema-validator.ts`. The local public PR-history object `7159f33c0a587c77fd9700fd25396b7a89edace6` reconstructs a first-add walk to exactly `6d88b9e1e9f24901985b1fb4e4200f18bd550e1b`; GitHub also associates that BIC directly with PR #24535. The BIC is not an ancestor of the squash, as expected for squash landing. Therefore `9729c2a5da7b59fdbf62b95c100e085a2c2daa4d` is the first mainline carrier, not the atomic BIC, and `squash_decomposed=true` with only `6d88b9e1e9f24901985b1fb4e4200f18bd550e1b` is correct.

## Affected and fixed releases

The CNA records `2.0.0` through `<2.33.4` and `2.34.0` through `<2.34.1` as affected metadata. Repository tag containment does not support that lower bound:

- Loader carrier `9729c2a5da7b59fdbf62b95c100e085a2c2daa4d` is absent from [`n8n@2.8.0`](https://github.com/n8n-io/n8n/releases/tag/n8n%402.8.0), tag commit `0b2e5d9cf0612cb828a7f74354243d73e2594ddd`, and first appears in [`n8n@2.9.0`](https://github.com/n8n-io/n8n/releases/tag/n8n%402.9.0), tag commit `8f4aed5cc2817606890348ee72b980aa802b7d58`.
- The advisory-specific MCP exposure commit `166eb85509b2409eb5e59f37dea96c849d0df790` is absent from [`n8n@2.24.0`](https://github.com/n8n-io/n8n/releases/tag/n8n%402.24.0), tag commit `6c321ea2a026ea5da6c32e3818455b1d3296bd78`, and first appears among regular local tags in [`n8n@2.25.1`](https://github.com/n8n-io/n8n/releases/tag/n8n%402.25.1), tag commit `d1c8049ddb5dd8013cca746e450c5933b8403462`. That tag contains both the MCP source and the still-unsafe loader.
- Verified affected endpoints [`n8n@2.33.3`](https://github.com/n8n-io/n8n/releases/tag/n8n%402.33.3), tag commit `12d3f08599176aeecd04c63f23ae7d4e0f4874e9`, and [`n8n@2.34.0`](https://github.com/n8n-io/n8n/releases/tag/n8n%402.34.0), tag commit `b533ecd6856fef9ba7ca096d14b1f798b9933ff6`, contain the carrier, the MCP exposure, and the raw join-to-`require` sink.
- [`n8n@2.33.4`](https://github.com/n8n-io/n8n/releases/tag/n8n%402.33.4), tag commit `14c9aef0552fb4776501ca1c4589451891dd0ef4`, contains fix backport `0405fc550f55051f6c459252f5860fa78d27ab80`; [`n8n@2.34.1`](https://github.com/n8n-io/n8n/releases/tag/n8n%402.34.1), tag commit `e2279d07cdc8d1aeee42607a15365ccfa98f8b27`, contains fix backport `170cfc787015d352488f6b6403af07a74e95ca1d`. The respective preceding endpoint tags do not contain those backports.

The defensible wording is therefore: the CNA declares the broad lower range, but code proves the loader only from `n8n@2.9.0` and the stated MCP exploit chain only from `n8n@2.25.1`; tested affected and fixed endpoints are as listed above. It is not defensible to repeat `2.0.0` as code-verified.

## Direct fix or unpatched state

Affected `n8n@2.34.0` still executes `require(schemaPath)` after the unsanitized joins. Public master fix [`ca3d42d8386515cd9f044377a15a632cd09b62f0`](https://github.com/n8n-io/n8n/commit/ca3d42d8386515cd9f044377a15a632cd09b62f0) directly changes this loader: it rejects NUL, separators, `.` and `..`; resolves the candidate with `require.resolve`; compares realpaths against `nodesRoot`; and requires only the contained resolved path. [PR #35563](https://github.com/n8n-io/n8n/pull/35563) exposes head member `c4488a956f3d48e53c5aa3cc6a99c5851e8b2009`; that object and squash `ca3d42d8386515cd9f044377a15a632cd09b62f0` have the same parent `a7dec6df87d2eaedffd22e7c8939804e350185a9` and identical tree `77033e2954d683a27c8ea0c6e32d3c8566a95907`, so no finer public fix member is exposed there.

The release-line fixes are [`0405fc550f55051f6c459252f5860fa78d27ab80`](https://github.com/n8n-io/n8n/commit/0405fc550f55051f6c459252f5860fa78d27ab80) for `2.33.x` and [`170cfc787015d352488f6b6403af07a74e95ca1d`](https://github.com/n8n-io/n8n/commit/170cfc787015d352488f6b6403af07a74e95ca1d) for `2.34.x`. The public direct-fix carrier remains `ca3d42d8386515cd9f044377a15a632cd09b62f0`; the backports establish the fixed release boundaries.

## BIC-only AI attribution

The exact atomic BIC object `6d88b9e1e9f24901985b1fb4e4200f18bd550e1b` has human author and committer `Mutasem Aldmour <mutasem@n8n.io>` and the explicit trailer `Co-Authored-By: Claude Opus 4.5 <noreply@anthropic.com>`. Because this same object first writes the unsafe path construction and dynamic load, the BIC-only result is **`AI_ROOT_CAUSE`**.

This judgment does not use the Claude trailer on squash carrier `9729c2a5da7b59fdbf62b95c100e085a2c2daa4d`, the separate Claude-marked MCP exposure `166eb85509b2409eb5e59f37dea96c849d0df790`, the bot-authored fix bundle, PR prose, or later refactors.

Keep `introducer_sha=6d88b9e1e9f24901985b1fb4e4200f18bd550e1b`, `introducer_parent=d5f2772381a8d91592fd47845fef5422f80cf9d9`, `introducer_parent_absent=false`, `squash_decomposed=true`, `decomposed_shas=[6d88b9e1e9f24901985b1fb4e4200f18bd550e1b]`, `direct_fix_sha=ca3d42d8386515cd9f044377a15a632cd09b62f0`, and verdict `AI_ROOT_CAUSE`.
2. Correct `bug_semantics` and `reasoning` so `2.0.0` is identified as CNA metadata contradicted by tag containment, not as a code-proven lower bound.
3. Record the two distinct code boundaries: unsafe loader carrier from `n8n@2.9.0`; advisory-specific MCP source-to-sink from `n8n@2.25.1`. Keep `n8n@2.33.3`/`n8n@2.34.0` as verified affected endpoints and `n8n@2.33.4`/`n8n@2.34.1` as verified fixed endpoints.

## Remaining gap

The vendor/CNA has not published a corrected lower bound reconciling its `2.0.0` range with repository history. The exact public first tag containing both required mechanisms is established as `n8n@2.25.1`, but this re-research does not replace vendor range metadata for every intervening build. Also, the original private fix member referenced by the public bundle is unavailable; the public same-tree fix carrier and two public backports are sufficient to verify the repair. Neither gap affects the BIC or BIC-only AI verdict.
