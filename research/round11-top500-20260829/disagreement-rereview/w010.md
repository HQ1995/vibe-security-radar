# w010 re-research

## Decision

**DISAGREE** with the disagreement memo's acceptance of a remaining BIC/identity gap. The memo and independent review are correct that `e6108c7997f5c8f7361b982959518e982b973230` is not an atomic BIC: its immediate parent is exploitable by the reported `template=` path. Fresh path decomposition nevertheless closes the gap with three public first-writes, all human-authored. Recommended primary verdict: **NOT_AI**, after correcting the introducer evidence. Recommended review verdict: **NOT_AI**.

## Vulnerability mechanism

The vendor advisory says that `Repo.clone_from(url, path, template=<dir>)` turns the keyword into `--template`, while the default clone denylist omits that option; Git copies the supplied template's hooks and executes `post-checkout`, giving command execution. It marks `<= 3.1.53` affected and `>= 3.1.54` patched ([vendor advisory](https://github.com/gitpython-developers/GitPython/security/advisories/GHSA-6p8h-3wgx-97gf)). The published CVE record independently describes the same `--template`/malicious `post-checkout` chain ([CVE-2026-73623](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2026/73xxx/CVE-2026-73623.json)).

I replayed that exact chain from exported local tag objects. Under `3.1.53^{commit}` = `faf3c09038b03bc2bdd8545ef34bbf6d7f1cd11f`, default `Repo.clone_from(..., template=...)` returned success and created the hook marker. Under `3.1.54^{commit}` = `e59d9bab02b095a97e179f47019afee95f4e3c18`, the same call raised `git.exc.UnsafeOptionError` and created no marker ([3.1.53 tag](https://github.com/gitpython-developers/GitPython/tree/3.1.53), [3.1.54 tag](https://github.com/gitpython-developers/GitPython/tree/3.1.54)).

The asserted primary BIC also fails dynamically: the same PoC succeeded and executed the hook at both `2625ed9fc074091c531c27ffcba7902771130261` and its child `e6108c7997f5c8f7361b982959518e982b973230`. The latter merely replaced an incomplete special-case guard with an incomplete denylist; it did not first create option forwarding or exploitability ([parent](https://github.com/gitpython-developers/GitPython/commit/2625ed9fc074091c531c27ffcba7902771130261), [child diff](https://github.com/gitpython-developers/GitPython/commit/e6108c7997f5c8f7361b982959518e982b973230)).

## Atomic BIC and immediate parent

The affected public entries decompose as follows.

1. `Repo.clone`: `00c5497f190172765cc7a53ff9d8852a26b91676` is the first public object to remove forced `bare=True` and expose a normal checkout clone while continuing to forward arbitrary `**kwargs`, including `template`. Its immediate parent `806450db9b2c4a829558557ac90bd7596a0654e0` exposes only `fork_bare`, forces `bare=True`, and therefore has no checkout in which `post-checkout` can run. This is a semantic first-write, not a rename-only refactor ([BIC diff](https://github.com/gitpython-developers/GitPython/commit/00c5497f190172765cc7a53ff9d8852a26b91676), [parent](https://github.com/gitpython-developers/GitPython/commit/806450db9b2c4a829558557ac90bd7596a0654e0), [Git clone `--bare` semantics](https://git-scm.com/docs/git-clone#Documentation/git-clone.txt---bare), [post-checkout semantics](https://git-scm.com/docs/githooks#_post_checkout)).
2. `Repo.clone_from`: `b425301ad16f265157abdaf47f7af1c1ea879068` first adds the classmethod and forwards its `**kwargs` to `git.clone`; immediate parent `ca288d443f4fc9d790eecb6e1cdf82b6cdd8dc0d` has `Repo.clone` but no `clone_from`. This is the atomic BIC for the vendor advisory's exact PoC entry ([BIC diff](https://github.com/gitpython-developers/GitPython/commit/b425301ad16f265157abdaf47f7af1c1ea879068), [parent](https://github.com/gitpython-developers/GitPython/commit/ca288d443f4fc9d790eecb6e1cdf82b6cdd8dc0d)).
3. Submodule option forwarding: `ba5717549b32f6b5cee304fdff87cb26b3be688a` first adds caller-controlled `clone_multi_options` to `Submodule.add` and `Submodule.update` and passes it into the existing `Repo.clone_from` route. Immediate parent `2d2ff037f9f7a9ae33e5f4f6bdb75b669a1af19a` has the internal clone call but no public `clone_multi_options` input ([BIC](https://github.com/gitpython-developers/GitPython/commit/ba5717549b32f6b5cee304fdff87cb26b3be688a), [parent](https://github.com/gitpython-developers/GitPython/commit/2d2ff037f9f7a9ae33e5f4f6bdb75b669a1af19a), [PR #1280](https://github.com/gitpython-developers/GitPython/pull/1280)).

Thus the smallest public BIC set is `00c5497f190172765cc7a53ff9d8852a26b91676`, `b425301ad16f265157abdaf47f7af1c1ea879068`, and `ba5717549b32f6b5cee304fdff87cb26b3be688a`; `e6108c7997f5c8f7361b982959518e982b973230` is excluded.
