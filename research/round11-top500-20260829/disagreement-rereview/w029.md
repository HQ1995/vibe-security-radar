## Vulnerability mechanism

At `cb5cd12a5882b59a8e441e84e636b2b960dc912f`, `create_safe_globals()` exposes CPython's raw `hasattr`, `getattr`, and `setattr`. The RestrictedPython path installs `_getiter_` and `_getitem_` but no `_getattr_`; it starts from RestrictedPython's builtins and then executes `merged_builtins.update(our_builtins)`, so the raw project-provided builtins win. `validate_code()` only searches source text for literal dangerous dunder names. A caller can therefore build names such as `"__cla" + "ss__"` at runtime, use raw `getattr` to traverse `__class__`, `__base__`, and `__subclasses__`, find `subprocess.Popen`, and execute with server-process privileges. The official advisory records this exact successful PoC path. [BIC source](https://github.com/IBM/mcp-context-forge/commit/cb5cd12a5882b59a8e441e84e636b2b960dc912f) [Repository advisory, vulnerability and PoC](https://github.com/IBM/mcp-context-forge/security/advisories/GHSA-xm98-3vcf-fph7)

The BIC's server entry point used stdio. Commit `7105ee0cb14c4faa3e202b895bdc52bf3a083121` later added unauthenticated HTTP transport; it amplified remote exposure but did not introduce or alter the raw-`getattr` sandbox bypass. [HTTP transport commit](https://github.com/IBM/mcp-context-forge/commit/7105ee0cb14c4faa3e202b895bdc52bf3a083121)
