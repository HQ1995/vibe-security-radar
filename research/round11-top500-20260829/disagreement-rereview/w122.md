# w122 re-research

## Decision

**AGREE** with the disagreement memo. Recommended primary verdict: `EVIDENCE_GAP`. Recommended review verdict: `EVIDENCE_GAP`.

The public Git history closes a coherent `allCustomerGroups` exposure lifecycle, but no first-party source uniquely binds that lifecycle to CVE-2025-49549 / GHSA-85jx-x9r4-45m2. The authoritative advisory instead describes a high-privilege issue spanning older release lines. Under the vulnerability-first, fail-closed protocol, the local BIC's human/no-AI signals cannot support `NOT_AI` for this advisory until that identity conflict is resolved ([Adobe APSB25-50](https://helpx.adobe.com/security/products/magento/apsb25-50.html), [CVE CNA record](https://cveawg.mitre.org/api/cve/CVE-2025-49549), [GHSA-85jx-x9r4-45m2](https://github.com/advisories/GHSA-85jx-x9r4-45m2)).

## Vulnerability mechanism

For the independently verified local mechanism, commit [`1b8236afe67fa961d4517e326ca278cb3daf406c`](https://github.com/magento/magento2/commit/1b8236afe67fa961d4517e326ca278cb3daf406c) adds the `Query.allCustomerGroups` schema field and `AllCustomerGroups::resolve()`. The resolver checks only `isShareAllCustomerGroupsEnabled()`, then returns codes from `GroupRepositoryInterface::getList()`; it has no user-type, login, or `Magento_Customer::group` authorization check. The same commit sets `customer/account_information/graphql_share_all_customer_groups` to `1`, and its added functional test invokes the query without an authorization header ([resolver](https://github.com/magento/magento2/blob/1b8236afe67fa961d4517e326ca278cb3daf406c/app/code/Magento/CustomerGraphQl/Model/Resolver/AllCustomerGroups.php), [default config](https://github.com/magento/magento2/blob/1b8236afe67fa961d4517e326ca278cb3daf406c/app/code/Magento/Customer/etc/config.xml), [functional test](https://github.com/magento/magento2/blob/1b8236afe67fa961d4517e326ca278cb3daf406c/dev/tests/api-functional/testsuite/Magento/GraphQl/Customer/GetAllCustomerGroupsTest.php)). By contrast, `/V1/customerGroups/search` routes the same repository `getList()` operation through the `Magento_Customer::group` ACL ([REST route](https://github.com/magento/magento2/blob/1b8236afe67fa961d4517e326ca278cb3daf406c/app/code/Magento/Customer/etc/webapi.xml)).

The reporter's first-party reproduction confirms that a request with no authentication returns customer-group names, and Adobe's LYNX-839 article reproduces `allCustomerGroups` and calls the GraphQL names exposed. Neither source names a CVE ([reporter reproduction](https://gist.github.com/damienwebdev/4f9a90c6cf3aceae468c6f6f5796f475), [Adobe LYNX-839 article](https://experienceleague.adobe.com/en/docs/experience-cloud-kcs/kbarticles/ka-27159)). Conversely, CVE-2025-49549 is `PUBLISHED`, but Adobe's CNA record says `PR:H`, describes a high-privileged attacker, and references only APSB25-50; APSB25-50 says authentication and admin privileges are required. Those claims do not identify this anonymous query path ([CVE CNA record](https://cveawg.mitre.org/api/cve/CVE-2025-49549), [Adobe APSB25-50](https://helpx.adobe.com/security/products/magento/apsb25-50.html)).

## Atomic BIC and immediate parent

For the local `allCustomerGroups` mechanism, the smallest surviving public first-write is `1b8236afe67fa961d4517e326ca278cb3daf406c`; its sole immediate parent is `f112c7a7bba2808d4046f22eacc76791634623db` ([BIC object](https://github.com/magento/magento2/commit/1b8236afe67fa961d4517e326ca278cb3daf406c), [parent object](https://github.com/magento/magento2/commit/f112c7a7bba2808d4046f22eacc76791634623db)). In the assigned local clone, `git log --all --reverse --diff-filter=A -- app/code/Magento/CustomerGraphQl/Model/Resolver/AllCustomerGroups.php` returns that BIC first. Exact tree checks against the immediate parent show that `AllCustomerGroups.php` does not exist and that neither `allCustomerGroups` nor `graphql_share_all_customer_groups` occurs. Thus parent absence is proven for the local mechanism.

This is not yet an advisory-level BIC: because CVE-2025-49549 has not been authoritatively tied to this mechanism, its true vulnerable lines and atomic introducer remain unresolved.

## Squash or member decomposition

`1b8236afe67fa961d4517e326ca278cb3daf406c` is a single-parent public commit, not a merge. Its commit-to-pull-request API returns an empty list, an exact repository search for `LYNX-732` returns no pull request, and the public commit object exposes no reconstructable member commits ([official commit object](https://api.github.com/repos/magento/magento2/commits/1b8236afe67fa961d4517e326ca278cb3daf406c), [commit-associated PRs](https://api.github.com/repos/magento/magento2/commits/1b8236afe67fa961d4517e326ca278cb3daf406c/pulls)). It is therefore the smallest surviving public object for the local mechanism; there is no evidence to label it a decomposable squash, and GitHub `web-flow` committer metadata alone does not prove squash provenance.

That conditional decomposition does not cure the advisory identity gap: a different CVE-2025-49549 mechanism could have a different BIC.

## Direct fix or unpatched state

## Corrections

- Change `introducer_parent_absent` from `false` to `true` for the local `allCustomerGroups` BIC: exact parent-tree checks prove absence.
- Replace the primary `NOT_AI` verdict with `EVIDENCE_GAP`; keep the review verdict `EVIDENCE_GAP`.
- Treat `1b8236afe67fa961d4517e326ca278cb3daf406c` and its human/no-AI metadata as conditional evidence for the local mechanism, not as the closed BIC for CVE-2025-49549.
- Do not attribute the CVE's older affected release lines to this mechanism: checked public history places the feature in 2.4.8 and its removal in 2.4.8-p1.
- Preserve `8c99a5941650ddd90912dd0c451f9c32f956bff9` as the named direct development fix and `10fdaddfd21f922d0c1b4f9f889dba8cfd4be8d6` as the independently landed release fix, without claiming that either vendor-associates this surface to CVE-2025-49549.

## Remaining gap

Obtain an Adobe/CNA source that explicitly and uniquely maps CVE-2025-49549 / GHSA-85jx-x9r4-45m2 to `allCustomerGroups` / LYNX-732 / LYNX-838 / LYNX-839, and that reconciles both contradictions: (1) the advisory's authenticated, admin, `PR:H` model versus the source/test/reporter's unauthenticated query, and (2) the advisory's older affected release lines versus the feature's checked 2.4.8-only public history. Until then, the advisory's actual vulnerable lines, BIC, parent, fix, and BIC-only AI attribution remain unclosed.
