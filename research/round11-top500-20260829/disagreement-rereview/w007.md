# w007 re-research

## Decision

**AGREE** with the disagreement memo. Recommended primary verdict: `FALSE_POSITIVE`. Recommended review verdict: `CORRECTION_REQUIRED`.

The published advisory describes a credentialed cross-origin attack, but the repository has no source-to-sink path by which a hostile website receives or automatically sends a victim's authority. The permissive CORS setting is real; the claimed cross-user vulnerability is not demonstrated.

## Vulnerability mechanism

The first-party advisory claims that any website can make authenticated API calls on behalf of a visitor. Its named configuration is present: `4c7ae852c784c9986d087c5956a77fa563a05a35` adds telemetry `CORSMiddleware` with `allow_origins=settings.cors_origins`, `allow_credentials=True`, and a default `cors_origins=["*"]` ([main.py](https://github.com/jahlives/openssl_encrypt/blob/4c7ae852c784c9986d087c5956a77fa563a05a35/server/telemetry-server/app/main.py#L23-L29), [config.py](https://github.com/jahlives/openssl_encrypt/blob/4c7ae852c784c9986d087c5956a77fa563a05a35/server/telemetry-server/app/config.py#L47)). `fafdfeed1b279cfe61e86cd8adc132b206eef8d4` later adds the same origin/credential combination to the key server ([main.py](https://github.com/jahlives/openssl_encrypt/blob/fafdfeed1b279cfe61e86cd8adc132b206eef8d4/server/key-server/app/main.py#L86-L92), [config.py](https://github.com/jahlives/openssl_encrypt/blob/fafdfeed1b279cfe61e86cd8adc132b206eef8d4/server/key-server/app/config.py#L35)).

The necessary victim-authority source is absent. Telemetry `/telemetry` and `/key/refresh` consume `HTTPBearer` credentials, while `/register` and `/stats` are unauthenticated ([telemetry.py](https://github.com/jahlives/openssl_encrypt/blob/4c7ae852c784c9986d087c5956a77fa563a05a35/server/telemetry-server/app/api/v1/telemetry.py#L15-L29), [register.py](https://github.com/jahlives/openssl_encrypt/blob/4c7ae852c784c9986d087c5956a77fa563a05a35/server/telemetry-server/app/api/v1/register.py#L17-L67), [stats.py](https://github.com/jahlives/openssl_encrypt/blob/4c7ae852c784c9986d087c5956a77fa563a05a35/server/telemetry-server/app/api/v1/stats.py#L14-L25)). The native telemetry client stores its key in a mode-0600 local file and explicitly constructs `Authorization: Bearer ...` ([api_key_manager.py](https://github.com/jahlives/openssl_encrypt/blob/4c7ae852c784c9986d087c5956a77fa563a05a35/openssl_encrypt/plugins/telemetry/api_key_manager.py#L68-L78), [uploader.py](https://github.com/jahlives/openssl_encrypt/blob/4c7ae852c784c9986d087c5956a77fa563a05a35/openssl_encrypt/plugins/telemetry/uploader.py#L68-L89)).

The key server likewise reads an explicit `Authorization` header for upload/revoke and leaves search public ([keys.py](https://github.com/jahlives/openssl_encrypt/blob/fafdfeed1b279cfe61e86cd8adc132b206eef8d4/server/key-server/app/api/v1/keys.py#L48-L84), [keys.py](https://github.com/jahlives/openssl_encrypt/blob/fafdfeed1b279cfe61e86cd8adc132b206eef8d4/server/key-server/app/api/v1/keys.py#L194-L211)). Its native client loads a token from a local mode-0600 file and explicitly adds the bearer header ([config.py](https://github.com/jahlives/openssl_encrypt/blob/fafdfeed1b279cfe61e86cd8adc132b206eef8d4/openssl_encrypt/plugins/keyserver/config.py#L185-L242), [keyserver_plugin.py](https://github.com/jahlives/openssl_encrypt/blob/fafdfeed1b279cfe61e86cd8adc132b206eef8d4/openssl_encrypt/plugins/keyserver/keyserver_plugin.py#L300-L327)). Exact-tree replay found no Cookie, session middleware, HTTP Basic/Digest, OAuth, client-certificate authentication, or browser JS/HTML client under either server. A hostile origin can send a bearer token it already knows; it cannot cause the browser to attach these native-client token files as victim credentials. The key server's acceptance of any non-empty bearer token is an independent authorization weakness, directly usable without a victim browser, and does not close the advisory's claimed CORS path.

## Atomic BIC and immediate parent

There is no vulnerability BIC because the claimed source-to-sink mechanism is incomplete. As lineage only, `4c7ae852c784c9986d087c5956a77fa563a05a35` is the earliest public first-write of the telemetry CORS block and wildcard default. It has the single immediate parent `457f88d09cc365cdbb85b083a29f0956804730be`; both telemetry paths are absent there, and exact-tree `git grep` finds none of `CORSMiddleware`, `cors_origins`, or `allow_credentials`. The later key-server copy is `fafdfeed1b279cfe61e86cd8adc132b206eef8d4`, whose parent is `4c7ae852c784c9986d087c5956a77fa563a05a35` ([candidate commit](https://github.com/jahlives/openssl_encrypt/commit/4c7ae852c784c9986d087c5956a77fa563a05a35), [copy commit](https://github.com/jahlives/openssl_encrypt/commit/fafdfeed1b279cfe61e86cd8adc132b206eef8d4)).

GitHub's first-party `commits/{sha}/pulls` endpoint returns an empty array, and no finer public member is reconstructable from the clone refs ([commit object](https://api.github.com/repos/jahlives/openssl_encrypt/commits/4c7ae852c784c9986d087c5956a77fa563a05a35), [associated PRs](https://api.github.com/repos/jahlives/openssl_encrypt/commits/4c7ae852c784c9986d087c5956a77fa563a05a35/pulls)). Repository membership is narrower: neither `4c7ae852c784c9986d087c5956a77fa563a05a35` nor `809416b74d2749cdcffb484cd65b057e1685cc13` is an ancestor of `v1.3.6` commit `f69305effbab0bdc0c8df0f2297cdfddf8929b6e`, whose tree has no named server CORS code; both are ancestors of `v1.4.0` commit `768df5cd1910e349509f07a27eeac6951e0003bf` ([v1.3.6 tag](https://github.com/jahlives/openssl_encrypt/releases/tag/v1.3.6), [v1.4.0 release](https://github.com/jahlives/openssl_encrypt/releases/tag/v1.4.0)). No tagged vulnerable release was found; only an unreleased development interval contained the advisory-named defaults, and the victim-authority mechanism is absent there too.

## Direct fix or unpatched state

`809416b74d2749cdcffb484cd65b057e1685cc13` directly changes both standalone defaults from `["*"]` to `[]` and adds production validation rejecting `"*"`; its parent `85cdb6bedf3a0fbfb49e2f2e29cd66f1f36f3101` retains both wildcard defaults ([hardening commit](https://github.com/jahlives/openssl_encrypt/commit/809416b74d2749cdcffb484cd65b057e1685cc13)). It reaches `releases/1.4.x` through merge `c1cbb36416ca300f604b1ba2771f96556f06a9b1` (parents `5836760a50d20d60b888486edde1fadc5dec24a6` and `74e20df6ebc854631fa61939243e5313966f9399`) and is an ancestor of `v1.4.0`. This is direct CORS hardening, not proof of a direct vulnerability fix.

## Corrections

- Replace primary `verdict: AI_ROOT_CAUSE` with `verdict: FALSE_POSITIVE`.
- Replace `bug_semantics` with the missing ambient-credential/source-to-sink explanation above.
- Set `flaw_origin`, `introducer_sha`, `introducer_parent`, `ai_marker`, `fix_sha`, and `direct_fix_sha` to `null`; retain the exact commits as non-vulnerability lineage and hardening evidence only.
- Do not describe telemetry `allow_methods` as wildcard: at `4c7ae852c784c9986d087c5956a77fa563a05a35` it is `["GET", "POST"]`, while the key-server copy uses `["*"]`.
- Do not report all released versions `< 1.4.0` as code-affected: the latest verified prior tag `v1.3.6` lacks the named server paths.

## Remaining gap

None for the repository-defined verdict. The vendor GHSA remains published and the CNA record remains `PUBLISHED`, but publication metadata repeats the same authenticated-cross-origin assertion and supplies no missing browser-ambient credential source. An unrecorded external deployment could add such a source, but no first-party object in this case establishes one; that hypothetical cannot sustain the current advisory claim.
