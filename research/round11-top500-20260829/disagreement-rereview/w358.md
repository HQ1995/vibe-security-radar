# w358 re-research

## Decision

**AGREE** with the disagreement memo. Recommended primary verdict: `NOT_AI`. Recommended review verdict: `CORRECTION_REQUIRED`, limited to recording the non-public enterprise release-membership gap; the independent review's causal `EVIDENCE_GAP` is not warranted.

The public objects close the vulnerability, atomic BIC, immediate-parent absence, direct fix, public OSS release boundaries, and BIC-only human attribution. The absent vendor-only artifacts do not make the BIC or its authorship ambiguous.

## Vulnerability mechanism

The vendor describes predictable reply correlation IDs in `RabbitTemplate.sendAndReceive()` with a fixed reply queue because of an internal simple counter; the CNA classifies this as CWE-330 and gives the same fixed-queue mechanism ([Spring advisory](https://spring.io/security/cve-2026-41701), [CVE-2026-41701 CNA record](https://github.com/CVEProject/cvelistV5/blob/main/cves/2026/41xxx/CVE-2026-41701.json), [GHSA-p5f7-rjhp-pxvc](https://github.com/advisories/GHSA-p5f7-rjhp-pxvc)).

The mechanism replays in the repository. In vulnerable `v4.0.3` commit `fd0b59e8c7a18d015556ef325b55cb19cc521306`, each `RabbitTemplate` owns an `AtomicInteger`; when no caller-supplied correlation ID is used, `doSendAndReceiveAsListener()` converts `incrementAndGet()` to the `messageTag`, installs it in `replyHolder`, and writes it into the request's AMQP `correlationId` or configured correlation header. `onMessage()` trusts that value to select the pending reply. Separate templates therefore restart and overlap the same small integer namespace on a shared fixed reply queue, so an early reply bearing the predictable tag can be delivered to the wrong pending request. The direct-fix commit states the same cross-instance reply-stealing cause ([v4.0.3 source](https://github.com/spring-projects/spring-amqp/blob/fd0b59e8c7a18d015556ef325b55cb19cc521306/spring-rabbit/src/main/java/org/springframework/amqp/rabbit/core/RabbitTemplate.java), [fix commit](https://github.com/spring-projects/spring-amqp/commit/ca163ae82281e979d4cf3a93ba51829aabbe3b59)).

## Atomic BIC and immediate parent

The atomic public BIC is `0a11c54328bf4d63beb8be609a84c0297b401ecc`, whose sole immediate parent is `5ce03d0d19892bae172c7fe892aee6278ec4f831` ([BIC](https://github.com/spring-projects/spring-amqp/commit/0a11c54328bf4d63beb8be609a84c0297b401ecc), [parent](https://github.com/spring-projects/spring-amqp/commit/5ce03d0d19892bae172c7fe892aee6278ec4f831)).

Repository replay with `git log --all --reverse -SmessageTagProvider -- RabbitTemplate.java` first returns `0a11c54328bf4d63beb8be609a84c0297b401ecc`. Its diff adds `private final AtomicInteger messageTagProvider = new AtomicInteger();` and changes the fixed-queue `messageTag` from `UUID.randomUUID().toString()` to `String.valueOf(messageTagProvider.incrementAndGet())`. Exact-object inspection of parent `5ce03d0d19892bae172c7fe892aee6278ec4f831` finds no `messageTagProvider` or correlation-tag `incrementAndGet()` and shows the fixed path still using `UUID.randomUUID().toString()`.

## Squash or member decomposition

No decomposition is applicable. `0a11c54328bf4d63beb8be609a84c0297b401ecc` is a standalone, one-parent AMQP-507 commit, not a merge or revert. Although it changes eight files for AMQP-507, the vulnerable counter field and both first sequential generation sites are written directly in that one exposed object; the public `-SmessageTagProvider` history exposes no finer member commit. Later history moves or removes the mechanism but does not reveal an earlier public member.

## Affected and fixed releases

The Spring advisory lists affected `4.0.0`-`4.0.3`, `3.2.0`-`3.2.10`, `3.1.0`-`3.1.15`, and `2.4.17 and earlier`; the structured CNA range makes the last maintained line explicit as `2.4.0` through `<2.4.18` ([Spring advisory](https://spring.io/security/cve-2026-41701), [CNA record](https://github.com/CVEProject/cvelistV5/blob/main/cves/2026/41xxx/CVE-2026-41701.json)).

The public release replay agrees where objects exist. The earliest listed public tags peel to `v2.4.0` commit `6235c7b3f7c1c2b6e4caa3b7ff65c6f383703432`, `v3.1.0` commit `1f62b1dc471969b3df9a075044b425d2882d0637`, `v3.2.0` commit `1661ee91560f4b6b9ce0a60ea424a3eca4c580a1`, and `v4.0.0` commit `6a5befef45583c95c7beccb7d03e2858ea14e190`; each contains the sequential generator and descends from the BIC. The public affected endpoints `v2.4.17` commit `6233960e9f5126f374525c514ff7c5b42eb84cd3`, `v3.2.10` commit `600d3908965c960280c2ce2313a5af9075c72a6b`, and `v4.0.3` commit `fd0b59e8c7a18d015556ef325b55cb19cc521306` also retain it ([repository tags](https://github.com/spring-projects/spring-amqp/tags)).

The vendor lists fixed versions `4.0.4` and `3.2.11` as OSS, plus `4.0.3.1`, `3.2.10.1`, `3.1.16`, and `2.4.18` as Enterprise Support Only ([Spring advisory](https://spring.io/security/cve-2026-41701)). Public `v4.0.4` commit `f047debc2618ba90e53dadac03c3960eae230072` contains backport `d822eef55359479e361423da78c63a72fd091efa`; public `v3.2.11` commit `251cb2527e9c34f8271b0653ceac91c97c1e0ac6` contains backport `1beed578185cfc23199ac353470432146e18b8ce`. Their immediate predecessors lack those backports, and both fixed tags use UUID at the two generation sites. The release notes bind that change to backport trackers [GH-3473](https://github.com/spring-projects/spring-amqp/issues/3473) and [GH-3474](https://github.com/spring-projects/spring-amqp/issues/3474) ([v4.0.4 release](https://github.com/spring-projects/spring-amqp/releases/tag/v4.0.4), [v3.2.11 release](https://github.com/spring-projects/spring-amqp/releases/tag/v3.2.11)).

## Direct fix or unpatched state

The originating direct fix is `ca163ae82281e979d4cf3a93ba51829aabbe3b59`, parent `4d2ca72ea59f320364d43698b031b9e11c843dba`. It deletes `messageTagProvider` and replaces both sequential tag-generation sites with `UUID.randomUUID().toString()` ([fix commit](https://github.com/spring-projects/spring-amqp/commit/ca163ae82281e979d4cf3a93ba51829aabbe3b59), [GH-3470](https://github.com/spring-projects/spring-amqp/issues/3470)).

The `4.0.x` backport is `d822eef55359479e361423da78c63a72fd091efa`, parent `0373cde52a9934d476079bceda445d948b70f112`; the `3.2.x` backport is `1beed578185cfc23199ac353470432146e18b8ce`, parent `1a9676e1b56c2d197d84d8940430e6b302929b51`. Both carry the same semantic change ([4.0.x backport](https://github.com/spring-projects/spring-amqp/commit/d822eef55359479e361423da78c63a72fd091efa), [3.2.x backport](https://github.com/spring-projects/spring-amqp/commit/1beed578185cfc23199ac353470432146e18b8ce)). This is a direct fix, not merely a release-note or mitigation claim.

## Corrections

- Keep the primary verdict `NOT_AI`; do not replace it with `EVIDENCE_GAP`.
- Change the independent review verdict from `EVIDENCE_GAP` to field-only `CORRECTION_REQUIRED`.
- Change primary `remaining_gap` from `null` to record that exact source/ancestry membership for vendor-only builds `4.0.3.1`, `3.2.10.1`, `3.1.15`/`3.1.16`, and `2.4.18` is not publicly replayable. This caveat does not alter the atomic BIC, direct fix, or BIC-only attribution.

## Remaining gap

Exact public Git refs or source artifacts were not found for the vendor-listed enterprise boundaries `4.0.3.1`, `3.2.10.1`, `3.1.15`, `3.1.16`, and `2.4.18`; exact `git ls-remote` queries return no matching refs. The vendor advisory is therefore authoritative for those product-build boundaries, while the public OSS `3.2.x` and `4.0.x` boundaries are independently replayed. No remaining gap affects the `NOT_AI` causal verdict.
