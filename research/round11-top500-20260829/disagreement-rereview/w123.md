# w123 re-research

## Decision

**DISAGREE** with the disagreement memo. Recommended primary verdict: **NOT_AI**. Recommended review verdict: **CONFIRMED**.

The memo's only stated gap—missing `2.4.4-p14` / `2.4.4-p15` tags—mixes the Adobe Commerce release line into a `magento/magento2` / Magento Open Source case. Adobe's product-specific table ends the affected Magento Open Source line at `2.4.5-p13 and earlier` and the fixed line at `2.4.5-p14`; only Adobe Commerce has `2.4.4-p14` / `2.4.4-p15`. GitHub's `magento/community-edition` package record likewise lists patched versions only through `2.4.5-p14`. The unavailable Commerce-only objects are therefore not a missing Open Source lifecycle gate.

## Vulnerability mechanism

CVE-2025-49554 is a published, non-withdrawn CWE-20 application denial-of-service reachable over the network without authentication or user interaction. Adobe assigns `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H`; the [CVE record](https://cveawg.mitre.org/api/cve/CVE-2025-49554), [Adobe APSB25-71](https://helpx.adobe.com/security/products/magento/apsb25-71.html), and [GHSA-xgfm-992v-h2hr](https://github.com/advisories/GHSA-xgfm-992v-h2hr) agree on those properties.

The source-level mechanism is GraphQL alias amplification. In affected tag `2.4.8-p1`, `QueryProcessor::process` parses attacker-controlled query text and, in production mode, calls `validateFieldCount()` and the webonyx complexity/depth validators before `GraphQL::executeQuery()`. Its configured field/complexity limit is 1000 and depth is 20, but it has no independent alias bound. Repeated aliases can therefore invoke many costly resolver selections within the old limits. The direct fix says that extremely large alias counts consume substantial resources, recursively counts every aliased `FieldNode`, rejects counts above the configured maximum, and defaults that maximum to 10. Its first-party functional test submits three aliased `products` selections under a limit of two and expects `Max Aliases in query should be 2 but got 3.` ([fix commit](https://github.com/magento/magento2/commit/f83cc26ca1d1dd027f939d67f68f7fa2b63951d9)).

This maps the otherwise generic vendor description of “specially crafted input” to the alias limiter with high confidence: among the APSB25-71 changes, this is an input-validation control expressly added to prevent GraphQL request resource exhaustion, matching CVE-2025-49554's unauthenticated CWE-20 DoS.

## Atomic BIC and immediate parent

The atomic public BIC is [d551d1e3f70f8ae09c4de6958125f22b855d5569](https://github.com/magento/magento2/commit/d551d1e3f70f8ae09c4de6958125f22b855d5569), `MAGETWO-81033: Create GraphQL endpoint for fetching single product` (2017-10-25). It first adds `app/code/Magento/GraphQl/Controller/GraphQl.php`; `dispatch()` accepts the request's `query` value and passes it directly to `\GraphQL\GraphQL::execute(...)` without an alias, field-count, complexity, or depth check.

Its sole immediate parent is [9ed7081088dcc2bf216aa374d43b2e8b7472160d](https://github.com/magento/magento2/commit/9ed7081088dcc2bf216aa374d43b2e8b7472160d). Replaying the parent tree with `git ls-tree` finds no `app/code/Magento/GraphQl` tree, and a bounded `git grep` finds no `GraphQL::execute` call under `app/code` or `lib`. Thus the vulnerable request-to-execution capability is absent in the immediate parent and first appears in the BIC.

Although the BIC is a 42-file feature commit, the public object has one parent, the GitHub commit-to-pulls API returns no associated PR, and no finer public member object exposes the endpoint first-write. It is therefore the smallest surviving public object permitted by the protocol.

## Direct fix or unpatched state

The direct mainline fix is [f83cc26ca1d1dd027f939d67f68f7fa2b63951d9](https://github.com/magento/magento2/commit/f83cc26ca1d1dd027f939d67f68f7fa2b63951d9), `AC-14323: Graphql query batching process enhanced` (2025-05-22). It has one parent, [54c59cf5d2150d8dc87f51b3a0f101b2f1531a22](https://github.com/magento/magento2/commit/54c59cf5d2150d8dc87f51b3a0f101b2f1531a22), whose tree has no `validateAliasCount`. The fix adds `MaximumAliasConfiguration`, enables `graphql/validation/alias_limit_enabled`, defaults `maximum_alias_allowed` to 10, adds recursive alias counting and rejection, invokes it before the older field-count and document validators, and adds functional coverage. ## Remaining gap

No protocol-blocking gap remains. Adobe does not publicly bind CVE-2025-49554 to a Git SHA or spell out “aliases” in the bulletin, so the CVE-to-fix mapping is a source-diff inference. It is nevertheless closed by the direct fix's explicit resource-exhaustion rationale, alias-limit implementation and functional test, the pre/post release replay, and the fact that this remedy uniquely matches the bulletin's unauthenticated CWE-20 application DoS.

The unavailable Adobe Commerce `2.4.4-p14` / `2.4.4-p15` source objects remain outside this Magento Open Source case and do not weaken its BIC or BIC-only authorship conclusion.
